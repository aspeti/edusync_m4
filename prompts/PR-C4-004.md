## 1. Anatomía del prompt

### 1.1 Role
```text
Eres un Senior Software Architect especializado en C4, DDD táctico y arquitectura hexagonal Java 21.
```

### 1.2 Task
```text
Genera el C4 Level 3 del contenedor domain-layer, con .mmd y .md espejo, mostrando puertos IN/OUT, servicios de dominio, Aggregate Roots, Value Objects y Domain Events sin dependencias Spring/JPA/AWS.
```

### 1.3 Context
```text
Fuentes: docs/arquitectura_hexagonal_EduSync.md, docs/fsd/FSD_EduSync.md, docs/DTI.md §5, ADR-0002, ADR-0004.
Destino: docs/diagrams/c4_level3_domain_layer.mmd + .md.
```

### 1.4 Reasoning
```text
1. Mapear FSD-UC-001/002/003/004/005/009 a puertos IN y servicios de dominio.
2. Separar puertos OUT de adaptadores externos.
3. Verificar dominio puro y Math.floor() solo en ConsolidacionDomainService.
4. Generar tabla de trazabilidad.
```

### 1.5 Stop condition
```text
Detente cuando .mmd y .md existan, C4Component sea válido, y validate confirme dominio sin Spring/JPA.
```

### 1.6 Output
```text

docs/diagrams/c4_level3_domain_layer.md
```

## 2. Invariantes del prompt

- `domain-layer` no importa Spring, JPA ni AWS SDK.
- `Math.floor()` solo aparece en `ConsolidacionDomainService`.
- `audit_log` se expresa como puerto/intención; escritura física fuera del dominio.
- `.mmd` y `.md` se versionan juntos (IG-09).
- Sin Unicode decorativo en labels (IG-10).
